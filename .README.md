# JSON-Translator-Toolkit

Простые скрипты для перевода текстов Unity. Запуск: `python имя_скрипта.py`.
Все пути считаются от папки проекта. Python-пакеты: `UnityPy`, а для `tt_*.py`
ещё `TypeTreeGeneratorAPI`. Для создания DummyDll нужны .NET и Il2CppDumper.

## JSON-диалоги (TextAsset)

1. Положи Unity-файлы в `Unity_Original`.
2. Запусти `unity_extract.py`: TextAsset появятся в `Files/Original`.
3. Запусти `export.py`: реплики появятся в `Files/OriginalStringOnly`.
4. Скопируй их в `Files/ModifiedStringOnly` и переведи.
5. Запусти `assets_checkNEW.py` для проверки.
6. Запусти `import.py`: JSON с переводом появятся в `Files/Output/Ready`.
7. Запусти `unity_pack.py`: готовые Unity-файлы появятся в `Unity_Modded`.

Из JSON выгружаются непустые строковые поля, имя которых заканчивается на `text`.
`ignore_list.txt` исключает точные имена полей и точные значения строк.
Обычные TextAsset вроде `Credits.txt` и `anonposts.txt` тоже выгружаются
по одной физической строке. Если перевода файла нет, `import.py` сохраняет оригинал.
Старые тексты Windows-1252 тоже читаются; при появлении русских букв они сохраняются как UTF-8.

## Реплики внутри level-файлов

1. Положи файлы `level0`, `level1` и т. д. в `Level_Original`.
2. Запусти `python 'level_extract(1).py'`.
3. Скопируй `Files/LevelOriginalStringOnly` в `Files/LevelModifiedStringOnly`, переведи.
4. Запусти `level_checkNEW.py`, затем `python level_packNEW..py`.
5. Результат — `Level_Modded`. Подпапки сохраняются.

Этот способ ищет реплики перед бинарным маркером `ExtraData`.
Он подходит только для диалогов с таким форматом.

## Текстовые поля через схемы Unity

1. Впиши путь к установленной игре в `GameDir.txt`.
2. Положи Il2CppDumper в `Tools/Il2CppDumper` и запусти `collect_dumps.py`.
   Результат — `Dumps/<имя папки игры>/DummyDll`.
3. Запусти `tt_extract.py`.
4. Скопируй `Files/TTOriginalStringOnly` в `Files/TTModifiedStringOnly`, переведи.
5. Запусти `tt_pack.py`. Результат — `Level_Modded`.

Список полей задан в `tt_fields.txt`: `+слово` ищет часть имени поля без учёта
регистра, `-поле` исключает точное имя. Это обычные слова, не регулярные выражения.
Файл правил обязателен. После изменения правил нужно заново извлечь текст.
Если схема IL2CPP не подходит к объекту, скрипт резервно извлекает
известные пользовательские строки: названия и описания предметов, имена
персонажей и названия частей тела. Остальные нечитаемые
классы выводятся одной сводкой и не засоряют лог сотнями одинаковых ошибок.

Оба паковщика level берут уже собранный файл из `Level_Modded`, если он есть,
чтобы сохранить предыдущие правки. Для сборки с нуля убери старый результат
из этой папки. При совместном использовании сначала собирай реплики, затем поля.
Не смешивай оригиналы разных версий игры.

## Формат перевода

Одна реплика занимает одну строку TXT. Сохраняй число и порядок строк.
Перенос внутри реплики записывается как `\n`, возврат каретки — `\r`,
обратная косая черта — `\\`. Пустые строки не удаляются и не сдвигают перевод.
Проверка помечает пустой перевод непустой реплики как ошибку.
Теги `<...>`, `{...}` и `[...]` должны сохраняться.

При неверном количестве строк или экранировании сборщик останавливается
с ошибкой. Исправь перевод и повтори запуск. Папка результата может содержать
файлы от предыдущих запусков; после неудачной сборки не используй её как готовую.
Скрипты не устанавливают перевод в игру: готовые файлы переносишь вручную.

## Что стало проще

- Одна папка `Files/Output/Ready` вместо нумерованных папок и поиска последней.
  Старые `ModifiedStringOnly_N` сохранены, но больше не используются.
- Проверки оставлены только для числа строк, пустых реплик, экранирования,
  служебных строк, переносов, тегов и плейсхолдеров. Предупреждения о латинице,
  длине перевода и ответах ИИ удалены.
- Ошибки в основном останавливают скрипт; широкие обработчики ошибок убраны.
- `collect_dumps.py` копирует только два необходимых файла IL2CPP и запускает Dumper.
  Можно передать путь к игре аргументом вместо `GameDir.txt`.
- Генератор схем создаётся один раз и используется для всех уровней.

`common.py` содержит чтение TXT и пути, `json_common.py` — выбор JSON-реплик,
`check_common.py` — общие проверки. `level_common.py` и `tt_common.py` содержат
необходимую работу с бинарными данными и схемами Unity.

`.Extra/importWithTab.py` — отдельный старый вариант импорта всех строк словарей
из `TxtFolder` и `TxtFolderTranslated` в `TxtFolderReady`, с отступами в JSON.
В основную цепочку он не входит.
